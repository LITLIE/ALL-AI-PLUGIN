### 实测确认的 P0 缺陷（有复现证据）
1. **Windows spawn 解析错误**（`core/utils.mjs` `findInPath`）：命中 npm 无扩展名 bash shim（`npm\claude`）而非 `.cmd`，`spawnPlan` 判 `.cmd` 失败 → `shell:false` → ENOENT。
   反证：`claude --version` = 2.1.258，`spawn(shell:true)` = code 0，唯独工作台报 ENOENT。
   **违反 ADR-002「复用 spawnPlan 禁止重写」——重写了一份错的。**
   修法：直接搬 `plugins/agent-crew/server/lib/dispatch.mjs` 的 `resolveExecutable`+`spawnPlan`（那份是对的）。
2. **Claude 适配器结构性无终态事件**：`run()` 只 yield 两次 `run.started`（L34/L91 重复），真事件走 `onEvent?.()`，但 `orchestrator._executeRun` **根本没传 onEvent** → 事件蒸发 → 必判 failed。
3. **Codex 轮询循环永不检测完成**：`codex-app-server.mjs` L102-113 只判超时，从不读 `notifications` → 每次运行必超时。
4. **适配器契约未传 agentConfig**：`agents/*.json` 的 command/args/env/timeoutDefault/maxRetries/riskLevel 全是死配置 → "配置驱动"名不副实，违反 AC-01。
5. **human-bridge 假阳性**：probe 恒 `{ok:true}` 显示 available，但 run 无终态事件 + submit 端点 501 → 端到端不通。
6. **测试零真实适配器覆盖**：`grep -rl "claude\|codex" test/` 零命中。
